# 场景、外设多配置与音频管理

## 页面

上方是横向场景卡片。下方每一行左侧显示具体外设，右侧显示该外设保存的多套配置。拖动配置到场景卡片即可绑定；也提供“绑定到场景”按钮。只有安装了匹配插件的实际外设，以及可用音频输出设备，才提供配置入口。已建立的配置在断连后保留。

场景详情可关联多个前台应用、查看和解除外设配置绑定。编辑场景可设置 0–1000 的优先级。一个应用匹配多个场景时，只启用最高优先级场景；同优先级按场景列表顺序选择。手动锁定后暂停自动切换，没有匹配时使用默认场景。

同一场景、同一具体外设只允许一套配置。拖入同一外设的另一套配置直接替换。不同场景可以绑定同一外设的不同配置。删除配置会清理所有引用，解绑不删除配置。

## 保存设备配置

1. 在外设行新建具名配置。
2. 打开对应设备插件，核对型号并连接。调整设备设置。
3. 在插件顶部“场景配置”选择具名配置，点击“读取当前设置并保存到所选配置”。
4. 返回场景页，将该配置拖入目标场景。

当前自有测试鼠标页面和 EV63 页面使用宿主注入的配置适配器。它们复用原协议的读取、写入和回读；根据具体设备 Container ID、VID/PID 与 HID Usage 匹配设备，不只按照型号匹配。未知插件需要实现 `window.hhubProfileAdapter`，不能将没有适配器的配置标记为已生效。

主程序通过后台离线插件实例执行场景配置，继续使用原有 HID 权限、报告长度和型号验证。没有设备、写入失败或回读不一致时显示等待或失败；可点击“重试应用”。连接变化、重试和配置修订会更新请求标识，过期回读被拒绝。

设置已保存或已绑定不等于设备已确认。关闭窗口时，有外设场景配置则隐藏到托盘，保留按需配置服务；从托盘完全退出会停止服务。未被新场景绑定的非音频外设保留最后设置，不猜测默认硬件配置。

## 耳机与后台音频

耳机插件确实声明并实现自身 EQ 控制接口时，新配置默认优先自身 EQ。否则使用通用 EQ；用户可以主动选择通用 EQ。只安装某个驱动不能证明宿主可控制其 EQ。当前没有已验证的耳机自身 EQ 插件；这部分使用插件能力接口，不能声称已在耳机上验证。

通用 EQ 配置保存输出设备和预设（包括自定义预设）。场景中的通用耳机配置仅用于此场景关联的应用。场景切换会撤销上一场景拥有的音频路由，保留独立后台绑定。

“音频管理”是独立分区，可按应用和输出分别保存 EQ，启用后台发声自动处理。背景绑定优先于场景音频配置，因此游戏前台不会覆盖音乐播放器的专用 EQ。同一应用可保存多个输出配置，但只启用一个。

耳机自身 EQ 一般作用于全部声音；使用通用逐应用 EQ 时，需要将自身 EQ 设为平直或关闭。未经插件确认不能宣称自身 EQ 已关闭。

包含 13 套 FxSound 工厂预设的 EQ 部分。保留原十段频率和增益，增加两段零增益以适配十二段宿主。不包含 FxSound 其他增强音效。原始预设和 AGPL 来源在 `vendor/fxsound`。
