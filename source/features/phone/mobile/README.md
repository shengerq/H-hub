# H hub 独立手机 App

先开发和验证 Android，Android 实机验证成功后再开发 iOS。现阶段没有 iOS 安装包。

## Android 0.4.0

原生 Java Android App，最低 Android 8.0（API 26），目标 API 36。无 WebView，界面和连接逻辑在 App 内运行。

功能：电脑系统监测、真实外设状态与电量、XInput 手柄振动测试、场景切换及自动模式、已保存设备配置选择和回读状态、12 段 EQ 调节、FxSound/自定义预设、按应用与输出区分的后台自动处理及启停。

EQ 处理电脑应用的音频，不处理手机本地音频。雷柏 VT3S MAX 通过现有桌面插件提供手机参数读取和调节：当前档位 DPI、DPI 档位选择、回报率、抬升高度、按下/释放延迟、休眠及已有开关参数。不要求先建立或保存场景配置。其他设备依插件适配能力显示具体原因；键盘灯效、宏和刷写不开放为通用手机操作。

## 连接

1. 安装 `android/build/Hhub-Android-0.4.0.apk`（开发签名）。
2. 手机与电脑接入可互访的可信局域网。
3. 运行新版电脑程序，进入“手机连接”启动服务。
4. 点击 App 的“扫描电脑二维码”；桌面默认生成 Android App 配对码。支持安装的原生扫码应用；没有时使用系统相机拍照后离线识别。也可使用系统扫码打开 hhub 链接、粘贴扫码结果或从相册识别。
5. 在电脑批准；要控制外设和 EQ，请勾选允许操作。

电脑证书通过二维码中的 SHA-256 指纹绑定，任何不一致均拒绝。授权在 Android Keystore 的 AES-GCM 密钥下加密存储；禁用系统备份。HTTP 明文及跨地址跳转不允许。撤销授权后 App 要求重新配对。暂不支持多个电脑连接。

原生配对调用 `/api/pair-status` 时传 `native: true`，电脑只向持有配对请求秘密且已获批准的请求返回一次 Bearer token。浏览器配对继续使用 HttpOnly Cookie。

## 蓝牙兜底辅助

App 和桌面提供系统蓝牙设置入口。Wi-Fi 不可用时，在手机系统开启蓝牙网络共享，Windows 与手机配对并连接 PAN，再在桌面刷新连接服务、选择蓝牙网卡地址重新扫码。流量依然使用 HTTPS、证书指纹和电脑审批。需要手机支持蓝牙网络共享及 Windows 支持 PAN；仅蓝牙配对并未建立网络。防火墙仍使用可信专用网络规则。

同一证书的地址变化可保留手机原授权；证书变化需要重新配对。没有实现独立 RFCOMM/GATT 数据隧道或静默开启蓝牙/共享。

## 0.4.0 EQ 界面

参考用户提供的 FxSound 页面，改成 H hub 风格的原生 Android EQ 页：顶部声音预设与应用/输出选择，12 段可拖动增益曲线、频率标签与旋钮；可展开单频段滑块精确调节。图形按频率排序，保存仍使用原始频段顺序，兼容已有配置。

横屏将处理控制置于左侧，曲线置于右侧；竖屏分区排列，可横向浏览全部频段。保留 H hub 深浅色、蓝色强调色、前级增益与自动衰减。旋转时保存未提交的 EQ 草稿。曲线显示频段增益，非实时频谱。

当前引擎为 FxSound 派生 Graphic EQ，尚未实现独立清晰度、环绕、氛围及动态增强模块；页面只接入已有音频能力。API 和桌面宿主无需更新。0.4.0 APK 构建与签名检查通过；尚未连接 Android 真机做视觉、旋转和触摸验证。

## 手机 UI 与外设控制

0.3.0 使用与桌面一致的背景、卡片边框和圆角、蓝色强调色及文字层级，支持 Android 系统深浅色。固定底部导航分别进入监测、外设、场景和 EQ；连接/蓝牙辅助移到顶栏菜单。遥测数字原位更新；其他页面只在数据变化时更新并保留滚动位置；EQ 草稿不会被轮询覆盖。

“我的设备”先读取真实设置，再通过原生选择框、数值框和开关调节。每次只提交一个受限参数。桌面插件重新读取当前设置，修改目标字段并执行已有写入/回读接口，保留其他参数。完成状态包含回读时间，超时/错误/权限撤销均不显示成功。

宿主可按需启动隐藏的插件工作窗口，手机不承载插件 WebView，也不发送任意 HID 报文。同型号多只设备在旧版雷柏协议下会被明确拒绝，避免操作错误设备。

当前桌面构建在工作区 `work/mobile-0.3-host`。本次已正常切换运行实例并恢复原局域网服务，保留原手机授权。安装 APK 更新后可继续连接。

## 升级兼容

手机不再把场景标为演示；设备配置只在插件回读后显示确认。后台 EQ 停止仅关闭选定应用/输出组合，不清除其他输出配置；运行状态来自实际音频流。预设使用桌面权威频率与增益。场景音频与独立后台绑定的优先级沿用桌面逻辑。

EQ 一次只显示一套应用/输出配置的滑块，避免批量创建所有编辑控件。未保存调节会阻止切换配置或其他控制操作，定时状态刷新不会覆盖草稿。图片识别在工作线程进行，解码尺寸受限，系统相机临时照片识别后删除。

本机验证：桌面/Android 构建与 APK v2/v3 签名通过；78 项核心自检通过；隔离实例上的二维码、原生 HTTPS、场景锁定/自动恢复、授权、服务重启与撤销测试通过。电脑连接的雷柏 VT3S MAX 已通过真实手机 HTTP 操作接口读取到 800 DPI、2000 Hz，并实际写入 850 DPI 后回读，再恢复 800 DPI并回读。未安装 0.3.0 到 Android 真机进行视觉检查；其他外设、蓝牙 PAN 和实际音频试听仍需验证。实际手机性能需真机测量。

现有桌面窗口/托盘核心可能仍是旧目录的版本。从托盘完全退出旧版，再启动本次新编译的 work/mobile-0.3-host/Hhub.exe，避免旧核心响应新手机请求。

## 构建

需要 JDK、Android SDK platform 36、Android SDK build tools 36.0.0、ZXing core 3.5.4。先运行 `android/fetch-dependencies.ps1` 下载并校验固定 SHA-256 的扫码依赖。运行 `android/build.ps1`；SDK 在其他位置时传入 `-AndroidJar` 和 `-BuildTools`，可用 `-SigningKey` 指定开发签名密钥，`-ZxingJar` 指定扫码依赖。默认工具路径位于工作区 `work` 目录。

构建脚本使用 javac、D8、AAPT2、zipalign 与 apksigner，生成并验证开发签名 APK。开发签名密钥不进 Git；正式分发需单独配置发布签名。

电脑服务验证运行 `source/test-phone.ps1`。原生连接层验证运行 `android/test-client.ps1`（需要 `org.json` JVM 测试库，通过 `-JsonJar` 指定）；它使用 APK 中同一个 `HubClient.java` 测试真实电脑服务的 TLS 指纹、Bearer 身份和只读权限，还验证桌面生成二维码的解析、旧码兼容、二维码图像往返识别及过期/重复参数拒绝；不包含 Android 界面或 Keystore 实机测试。

## Android 验收后再进入 iOS

- 实机安装并正常启动，原生扫码/系统相机/相册各路径完成配对。
- 在实际手机与电脑上验证蓝牙 PAN 网络共享及重新扫码。
- 正确指纹配对成功，错误指纹被拒绝。
- 只读设备不能控制，允许操作后可以控制，撤销后不能继续访问。
- 监测数据与电脑一致，切到后台停止轮询，恢复前台继续。
- 实物手柄测试振动，断线时返回错误。
- 已配置真实音频路由的电脑上验证 EQ 调节、旁路、启停及实际听感。
- 网络中断、重连、进程重启和授权恢复通过。

构建和电脑协议测试不能代替上述手机及硬件实机验收。
