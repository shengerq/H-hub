# UI 内存检查与修复

日期：2026-10-14。

## 已确认的额外占用

- 趋势历史原先保存完整监测快照，包括原始传感器和磁盘列表；现在只保存时间戳、CPU/GPU/内存读数及曲线需要的三个字段。仍保留 60 秒和 90 个样本的上限。
- 首页曲线每次刷新都删除、重建 Polyline；现在复用图形，只更新采样点，保留缺失数据时断线的行为。
- 插件市场搜索、状态更新会重建列表，原先每次向页面事件清理数组追加记录，直到离开整个页面才清理。现在动态列表有自己的清理范围，每次重建先撤销旧事件。
- 图片异步加载原先持有 Image 强引用；现在使用弱引用，已移除的图片不再因加载任务而继续存活。小图片按显示尺寸与 DPI 解码，不再统一解码到 700 像素高。
- 更新和应用列表轮询原先没有并发保护；现在同类请求只保留一个，页面切换后丢弃过期结果。
- 场景页双击、拖放及菜单事件纳入页面清理。最后一个插件视图和后台配置视图关闭后，释放共享 WebView 环境引用；仍保留后台配置实际需要的视图。

## 验证

Release x64 构建通过。95 项核心自检通过，包括构造 500 项大传感器数据、确认趋势缓存排除大数组且保留 0 和不可用读数的回归检查。

普通切页模拟测试：修改前后各完成 600 次切页，均没有旧页面残留。第 120 次之后私有内存平均分别为 49.44 MB 和 48.22 MB，峰值分别为 52.52 MB 和 51.26 MB。这是单次观测，不能据此宣称大幅降低内存或完全修复长时间泄漏。

最终压力测试增加 40 项模拟插件列表，每次进入市场重建 10 次，检查动态事件记录是否累积。最终数据见 ui-memory-final.csv 和 ui-memory-comparison.json。

测试使用独立实例和模拟后台，不连接用户的核心、设备或手机，不激活前台窗口。模拟测试不包含真实插件 WebView、实际硬件采集或前台绘制开销，不能将测试内存当作真实应用的目标值。

真实进程只读观测：UI 私有内存约 77–90 MB；Core 约 6.6–6.8 MB，Phone 约 25.4 MB，Sensors 约 24.6 MB。观测时未发现属于 H hub 的 WebView 子进程。当前监测快照约 2.2 KB、原始传感器行数 0，因此趋势压缩在当前虚拟机上的节省有限；真实硬件回传较大时节省会更多。

本轮未复现旧页面无限累积，已处理可确认的多余缓存、事件记录积累与资源生命周期问题。小时级运行和真实插件切换仍需要进一步观察。没有使用清空工作集或隐藏子进程的方式改变统计。
最终加压测试完成：600次切页、670次40项插件列表重建（共26800行），旧页面存活数始终0，市场事件记录始终83；前段均值58.10MB、后段58.52MB，后段范围54.69–62.88MB。通过资源残留断言。
